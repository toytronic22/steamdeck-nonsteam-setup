# Оформить новые игры

[English](README.md) · **Русский**

Для Steam Deck. Добавил в Steam игру не из Steam (репак, GOG, что угодно с `.exe`) — через несколько секунд
ярлык сам получает всё, что было бы у оригинала:

1. **Имя** — если ярлык назван по exe (`VRising.exe`), он становится `V Rising`.
2. **Картинки** из магазина Steam: постер, фон, логотип с родной позицией и широкая обложка.
   Картинки, которые ты поставил сам, не трогаются.
3. **Proton** — принудительно тот, с которым игра чаще всего работает по хорошим отчётам ProtonDB.
4. **Раскладка контроллера** — как у оригинала в Steam.
5. **Выбор раскладки** — в меню контроллера ярлыка видны официальные раскладки и раскладки сообщества
   оригинала: можно выбрать любую, как у купленной игры. Раскладки под Steam Deck — сверху, по числу установок.
6. **Библиотеки** — Visual C++, DirectX и OpenAL, которые Steam ставит оригиналу перед первым запуском, и старый PhysX.
   Без них игра пишет «Microsoft Visual C++ 2015–2022 Redistributable required» или падает с «General protection
   fault» (Batman: Arkham Asylum без PhysX).
7. **Запуск** — ярлык, который ведёт на настройщик графики вместо игры, переводится на exe игры.

Кнопка «Оформить новые игры» в Steam делает то же самое вручную и показывает отчёт: что нашлось, что
поставлено и почему. Если новых игр нет — показывает последний отчёт, в том числе автоматический.

Окна и отчёты программы пока только на русском. Установщик говорит по-русски или по-английски — по языку системы
или Steam; задать явно: `… | NONSTEAM_LANG=ru bash` (или `en`).

## Установка

В режиме рабочего стола открой Konsole и вставь:

```bash
curl -fsSL https://raw.githubusercontent.com/toytronic22/steamdeck-nonsteam-setup/main/get.sh | bash
```

Установщик:

- кладёт программу в `~/.local/share/nonsteam-setup/app` — без root и без изменений в системе;
- добавляет кнопку «Оформить новые игры» в Steam (раздел ярлыков не из Steam, со своими картинками)
  и на рабочий стол;
- включает автоматический режим — службы systemd пользователя;
- спрашивает, включить ли порт отладки Steam ([ниже](#порт-отладки-steam-и-безопасность)), — без него программа
  не работает. После включения перезапусти Steam или деку, кнопка появится сама.

Без вопроса: `… | bash -s -- --enable-port` или `… | bash -s -- --no-port`. Из клона репозитория: `bash install.sh`.

Нужно: SteamOS или другой Linux со Steam не из Flatpak, systemd пользователя, Python 3.9 или новее; для окон —
`zenity` (в SteamOS есть). Нужна сеть: магазин Steam, GitHub (база ProtonDB и проверка обновления) и, про запас,
`api.steamcmd.net`. Ключи API не нужны.

## Порт отладки Steam и безопасность

Программа говорит с самим Steam через его порт отладки `127.0.0.1:8080` — тем же путём, что плагины Decky Loader.
Поэтому всё применяется сразу, без перезапуска Steam, и так же, как если бы ты выставлял это руками в свойствах
игры.

**Риск.** Пока порт открыт, к Steam может подключиться любая программа на этом устройстве, в том числе игра не из
Steam, и действовать от имени твоего аккаунта Steam. Снаружи, по сети, порт недоступен. Включай, только если
доверяешь тому, что запускаешь. Если у тебя стоит Decky Loader, порт у тебя уже открыт.
Удалишь Decky — его удальщик выключит порт: запусти установку ещё раз, она спросит, включить ли его снова.

Порт включается и выключается и в самом Steam: «Настройки» → «Система» → «Включить режим разработчика», затем
«Настройки» → «Разработчикам» → «Удалённая отладка CEF». Установщик делает то же самое: создаёт файл
`~/.local/share/Steam/.cef-enable-remote-debugging`. Steam читает его при запуске.

## Обновление

Та же команда, что для установки. Настройки, отчёты и уже оформленные игры сохраняются.

Последняя строка отчёта кнопки показывает версию и есть ли новее. Программа узнаёт это по файлу `VERSION` на
GitHub не чаще раза в шесть часов. Сама она не обновляется.

## Удаление

```bash
bash ~/.local/share/nonsteam-setup/app/uninstall.sh
```

Убирает службы, кнопку из Steam и с рабочего стола, саму программу. Порт отладки выключает, только если его
включил наш установщик, и сначала спрашивает. Данные (отчёты, журналы, кэш ProtonDB, копии файлов Steam) — тоже
с вопросом; `--purge` удаляет их без вопроса, `--keep-data` оставляет.

Картинки, Proton, раскладки и библиотеки, которые программа поставила играм, остаются. Раскладки оригинала в меню
контроллера пропадут после перезапуска Steam.

## PhysX: скачать один раз руками

Старым играм на PhysX (Batman: Arkham Asylum и подобным) нужен установщик PhysX от NVIDIA. Программа ничего не
качает сама, поэтому его кладут один раз (28 МБ, сумма та же, что у winetricks):

```bash
mkdir -p ~/.local/share/nonsteam-setup/redist/PhysX && cd ~/.local/share/nonsteam-setup/redist/PhysX && curl -fLO https://us.download.nvidia.com/Windows/9.23.1019/PhysX_9.23.1019_SystemSoftware.exe && echo "9b42b84e881769d681e09f62a1b51532616b2e6a2d5d99d0ccae6eb5fbbc208c  PhysX_9.23.1019_SystemSoftware.exe" | sha256sum -c
```

Нет файла — в отчёте «нет на деке: PhysX» и эта подсказка.

## Как выбирается Proton

Берутся отчёты ProtonDB «работает» за последние два года (если их меньше трёх — за всё время) и считается,
какой Proton в них встречается чаще.

| Победил в ProtonDB | Что ставится |
|---|---|
| «official» — стабильный Proton | новейший установленный стабильный Proton |
| «experimental» | Proton Experimental |
| GE-Proton | та же версия GE, если стоит; иначе новейший GE; GE нет совсем — следующий вариант |
| старый Proton (5.13, 7.0…) | он же, если есть в Steam; иначе следующий вариант |
| отчётов меньше трёх или ничья | Proton Experimental |

База ProtonDB (выгрузка `bdefore/protondb-data`, около 70 МБ) скачивается при первом запуске и обновляется
раз в месяц. Без сети берётся старая.

## Как выбирается раскладка

1. Официальная раскладка разработчика из Steam, если есть.
2. Игра полностью поддерживает геймпад — шаблон «Геймпад».
3. Иначе — самая популярная раскладка сообщества для оригинала (Steam сам её скачивает).
4. Сообщества нет: частичная поддержка — «Геймпад», никакой — «Геймпад с высокоточными осями».

Если у ярлыка с таким именем раскладка уже есть (ставил сам), её не трогаем.

## Библиотеки: Visual C++, DirectX, OpenAL и PhysX

Купленной игре Steam перед первым запуском ставит в её префикс Proton библиотеки, которые заявил разработчик.
Ярлыку — никогда, поэтому репаки падают с ошибками «нужен Visual C++ …». Программа делает то же, что Steam:

- **что ставить** — смотрит, какие пакеты Steam оригинал требует (список в appinfo игры, спрашивает у самого Steam);
  Visual C++ 2015–2022 ставится всегда: он нужен почти всем новым играм и ничему не мешает;
- **откуда** — из «Steamworks Shared» на самой деке: это установщики Microsoft, которые скачал сам Steam. Чего
  там нет, программа просит скачать сам Steam (ниже). PhysX — из
  `~/.local/share/nonsteam-setup/redist/PhysX/` ([выше](#physx-скачать-один-раз-руками)). Установщики из папки
  игры или репака не запускаются никогда;
- **куда** — в префикс ярлыка (`compatdata/<номер ярлыка>`) тем Proton, который выбран игре. Префикса ещё нет —
  он создаётся сразу, как при первом запуске.

| Пакет Steam | Что ставится |
|---|---|
| Visual C++ 2015, 2017, 2019, 2022 | Visual C++ 2015–2022 (новейший из Steamworks Shared, он подходит и старым) |
| Visual C++ 2005, 2008, 2010, 2012, 2013 | тот же год |
| DirectX Jun2010 | DirectX (`DXSETUP.exe /silent`) |
| .NET, XNA | ничего: Proton заранее помечает их установленными и даёт свой Wine Mono — Steam тоже их не ставит |
| PhysX | PhysX 9.23.1019 от NVIDIA (`/s`): все движки 2.7.1–2.8.3 и новее, путь `PhysX\Common` в PATH префикса |
| OpenAL | OpenAL от Creative (`oalinst.exe /s`) |

PhysX нужен не только тем, кому его заявил Steam. Старые игры (например, Batman: Arkham Asylum)
ставят его своим установщиком, который Steam запускает из папки игры, — в appinfo его нет. Поэтому признак ищется
в файлах игры: exe или dll рядом упоминает `PhysXLoader.dll`, а своего `PhysXCore.dll` рядом нет, — нужен PhysX.
Новые игры на PhysX 3–5 возят его с собой, им не нужно. OpenAL ставится только тем, кому его заявил Steam: такой
же признак по `OpenAL32.dll` срабатывал зря — у Stardew Valley своя копия под другим именем (`soft_oal.dll`),
Batman упоминает его, а Steam оригиналу его не ставит. Признак считается один раз на exe и хранится в
`state.json` (`local`, `checks` — какие признаки искали; добавится новый — все игры проверятся заново один раз).

Строка отчёта «библиотеки»: что поставлено, что уже было, чего нет на деке. Steam держит в Steamworks Shared только
пакеты, нужные установленным купленным играм, поэтому, например, Visual C++ 2010 там может не оказаться — тогда
программа скачивает его через Steam сама: отправляет в консоль Steam через порт отладки `download_depot 228980
<депо>` и ждёт в `logs/console_log.txt` строку Steam «Depot download complete» или «Depot download failed» — по
одному пакету, каждый не дольше 5 минут. Steam кладёт файлы в
`~/.local/share/Steam/ubuntu12_32/steamapps/content/app_228980/`, программа ставит оттуда. Пакеты маленькие
(Visual C++ 2005 — 6 МБ, OpenAL — 1 МБ), это те же файлы, что Steam качает купленным играм. Не скачалось — в отчёте
причина от Steam; кнопка пробует снова при каждом нажатии, автоматический запуск бросает после трёх неудач.

| Пакет | Депо Steamworks Shared |
|---|---|
| Visual C++ 2005 | 228981 |
| Visual C++ 2008 | 228982 |
| Visual C++ 2010 | 228983 |
| Visual C++ 2012 | 228984 |
| Visual C++ 2013 | 228985 |
| Visual C++ 2015–2022 | 228989 |
| DirectX | 228990 |
| OpenAL | 229020 |

Проверка, что пакет встал, — по реестру префикса (запись «Microsoft Visual C++ … Minimum Runtime» и подобные)
и по файлам: для DirectX — `d3dx9_43.dll`, настоящий он или заглушка Wine, для OpenAL — `OpenAL32.dll`, для PhysX —
`Program Files (x86)/NVIDIA Corporation/PhysX/Common/PhysXLoader.dll`. Проверяется и при каждом запуске: если
префикс пересоздали (удалил, сменил Proton с очисткой), библиотеки ставятся заново, в отчёте — раздел «Библиотеки
для уже оформленных игр». Запущенную игру программа не трогает: поставит после выхода. Запустил игру прямо во
время установки — программа не будет доустанавливать и не тронет Wine (иначе закрыла бы игру), попытка не
засчитывается, остальное — после выхода. Пакет, который не встаёт три раза подряд, больше не пробуется, журнал
установки — `~/.local/share/nonsteam-setup/logs/redist-<номер ярлыка>.txt`. Перед установкой реестр префикса
копируется в `~/.local/share/nonsteam-setup/prefix-backups/` (три последние копии).

## Раскладки оригинала в меню контроллера

Steam ищет раскладки по номеру игры, а у ярлыка свой номер, поэтому сам он показывает ярлыку только твои
раскладки и шаблоны. Программа подмешивает в этот список официальные раскладки и раскладки сообщества
оригинала: «Настройки контроллера» → «Текущая раскладка» → вкладки «Официальные раскладки» и
«Раскладки сообщества». Выбранная раскладка ставится ярлыку, как и любая другая.

Во вкладке «Раскладки сообщества» сверху идут раскладки, сделанные под Steam Deck, — от самой популярной: в начале
названия написано, сколько человек её установили, например «6 332 установки на Steam Deck · V-Rising for steam
deck». Ниже — раскладки для других геймпадов, в порядке Steam. В обычном ответе Steam раскладок под Steam Deck
нет, поэтому программа запрашивает у него раскладки оригинала для всех контроллеров и берёт из них
сделанные под Steam Deck. Число установок Steam подгружает за секунду-две после открытия вкладки, тогда же список
переставляется. Полного списка Steam не отдаёт: для одних игр в ответе есть самые популярные раскладки под Steam
Deck, для других — только малоизвестные с нулём установок.

Официальной раскладкой разработчик иногда назначает обычный шаблон Steam (у Solarpunk — «Геймпад с управлением
камерой»). Такой шаблон у ярлыка уже есть среди шаблонов, поэтому он не добавляется второй раз, а просто
показывается и во вкладке «Официальные раскладки», как у купленной игры.

Подмешивание живёт только в памяти Steam и ничего не пишет в файлы. После перезапуска Steam его за несколько
секунд возвращает служба `nonsteam-layouts.service`. Работают ли сейчас раскладки оригинала, пишет строка
отчёта кнопки:

- «подключены, игр — N» — всё в порядке;
- «не подключились: …» — Steam обновился и внутри что-то поменялось, нужна правка программы;
- «не работает служба» — после перезапуска Steam раскладки оригинала из меню пропадут, поможет повторная установка;
- «выключены предохранителем» — см. ниже.

**Предохранитель.** Если Steam три раза подряд теряет связь меньше чем через минуту после того, как служба
подключила раскладки, служба перестаёт их подключать: вдруг новая версия Steam от этого падает. Остальное
работает как раньше. Включить снова — запустить установку ещё раз.

У некоторых игр раскладок нет и у оригинала (например, Graveyard Keeper 2), тогда и подмешивать нечего.

Выключить: `systemctl --user disable --now nonsteam-layouts.service`, раскладки оригинала пропадут из меню после
перезапуска Steam. Журнал: `journalctl --user -u nonsteam-layouts`.

## Что обрабатывается

Ярлыки, у которых запускаемый файл — `.exe`, `.bat` или `.cmd`, и только один раз: обработанные записываются в
`~/.local/share/nonsteam-setup/state.json`. Chrome, VLC и прочие родные программы не трогаются. Профиль Steam —
тот, в который входили последним.

Название ищется по очереди: имя ярлыка (если оно не exe), папки над exe, имя exe по словам
(`GraveyardKeeper2` → `Graveyard Keeper 2`). Из названий убираются версии, `[v1.2]`, `RePack` и подписи
сборщиков в конце: `Игра by Кто-то`, `Игра - Кто-то`, `Игра-Кто-то`. Каждое название пробуется и целиком, и без
такого хвоста, поэтому настоящие названия с тире не теряются. В магазине берётся точное совпадение (знаки `™`, `®`
не мешают), затем совпадение без издания в конце («Game of the Year Edition», «GOTY», «Complete», «Definitive»,
«Special Edition», «Remastered» и подобные: `Batman Arkham Asylum GOTY` → «Batman: Arkham Asylum Game of the Year
Edition», `The Witcher 3 Wild Hunt` → «The Witcher 3: Wild Hunt — Remastered»), затем с частью названия после
двоеточия или тире (`Skyrim Special Edition` → «The Elder Scrolls V: Skyrim Special Edition») или до них — только
если такая игра одна: `Batman` подходит и к Arkham Knight, и к Arkham City, поэтому не берётся никакая. Поиск
магазина ничего не вернул — тот же поиск через сообщество Steam. Берутся только игры: дополнения, книги и
саундтреки с похожим названием пропускаются (иначе `Solarpunk` находил «Solarpunk – Official Book»). Не нашлось —
игра не трогается, в отчёте сказано, какие названия пробовали: переименуй ярлык в точное название игры, и она
оформится сама.

**Ярлык на настройщик.** В Steam у игры бывает несколько вариантов запуска: сама игра и, например, настройщик
графики. Если ярлык ведёт на вариант, который Steam подписывает как настройки («Settings», «Config», «Options»,
«Setup»), а основной вариант лежит рядом на диске, программа переводит ярлык на основной exe и его рабочую папку.
В отчёте: «ярлык вёл на … — перевёл на игру: …». На лаунчер ярлык не переводится никогда.

**Ярлык на лаунчер.** Если exe — лаунчер (в имени есть `launch`), он остаётся как есть, а в отчёте подсказка: если
кнопки лаунчера не видны или не нажимаются (старые лаунчеры под Proton), направь ярлык на exe игры — и до трёх
подходящих exe рядом. У Batman: Arkham Asylum это `Binaries/ShippingPC-BmGame.exe` вместо `Binaries/BmLauncher.exe`,
настройки графики тогда меняются в самой игре.

Ярлык ведёт не на программу (на `.dll`, `.ini`, картинку — так бывает, если в окне «Добавить стороннюю игру»
случайно выбрать не тот файл) — Steam его не запустит. Такой ярлык не оформляется, в отчёте: «ярлык ведёт на файл
.dll, а не на программу», какие exe есть рядом и что делать — удалить ярлык и добавить exe игры.

Слабое место — бессмысленное короткое имя папки, которое случайно совпало с настоящей игрой (`xyz` → игра
«XYZ»). Тогда ярлык получит картинки и Proton чужой игры.

## Автоматический режим

Установщик включает службы systemd пользователя:

- `nonsteam-setup.path` следит за `shortcuts.vdf` каждого аккаунта Steam на устройстве: Steam переписывает его при
  добавлении и переименовании ярлыка, через 5 секунд запускается `run.sh --auto`;
- `nonsteam-setup.timer` — запасная проверка раз в 10 минут и через 3 минуты после включения: на случай, если в
  момент добавления Steam ещё не был готов;
- `nonsteam-layouts.service` — раскладки оригинала в меню контроллера (см. выше), работает всё время. Если при
  установке порт был закрыт, эта же служба добавит кнопку в Steam, когда порт откроется.

Автоматический запуск без окон. Пустой запуск (новых игр нет) ничего не делает и ничего не пишет. Игру, которую
не нашёл в магазине, он больше не трогает, пока ярлык не переименуют; при других ошибках пробует три раза.
Кнопка пробует всегда.

Выключить: `systemctl --user disable --now nonsteam-setup.path nonsteam-setup.timer`.
Журнал: `journalctl --user -u nonsteam-setup`.

Перед каждым запуском копируются `shortcuts.vdf`, `config.vdf` и файлы раскладок в
`~/.local/share/nonsteam-setup/backups/` (последние десять).

## Запуск руками

```bash
~/.local/share/nonsteam-setup/app/run.sh              # новые игры, с окнами
~/.local/share/nonsteam-setup/app/run.sh --no-gui     # то же, отчёт в терминал
~/.local/share/nonsteam-setup/app/run.sh --dry-run    # только показать, что найдено
~/.local/share/nonsteam-setup/app/run.sh --all        # оформить заново все ярлыки
~/.local/share/nonsteam-setup/app/run.sh --appid 2286911949
~/.local/share/nonsteam-setup/app/run.sh --auto       # как служба: без окон, сдавшиеся игры пропускает
```

Последний отчёт кнопки или службы лежит в `~/.local/share/nonsteam-setup/last-report.txt` — его кнопка
показывает, когда новых игр нет. Пробный прогон и `--appid` пишут отдельно, в `manual-report.txt`, и его не
затирают.

## Почему так устроено

- Регистрировать свои обработчики в `SteamClient.*.RegisterFor…` нельзя: слот один, свой обработчик
  выкидывает обработчик Steam, и меню раскладок перестаёт получать данные. Поэтому раскладки берутся через
  внутреннее хранилище Steam, которое ими уже пользуется.
- Раскладка ярлыка в Steam привязана к его **имени**, поэтому сначала переименование, потом раскладка.
- Список раскладок в меню подложить файлом нельзя: Steam каждый раз запрашивает его заново по номеру игры.
  Поэтому подменяются два метода того же хранилища раскладок — и только на нём самом, код Steam не меняется.
  Число установок берётся из сведений о раскладках, которые Steam сам загружает для вкладки (там же лайки).
  Хранилище ищется среди уже загруженных модулей Steam, новые модули при этом не запускаются.
  Служба проверяет подмену раз в 5 секунд и ставит заново, если Steam перезапустился или в `state.json`
  появились новые игры.
- Всплывающего уведомления в игровом режиме нет: свои уведомления Steam снаружи не рисует. Поэтому состояние
  показывает кнопка — последний отчёт.
- Окна (`zenity`) запускаются с `LC_ALL=C.UTF-8`: из Steam кнопка стартует без UTF-8, и zenity отвергает
  русский заголовок («This option is not available»), окно не появляется.
- Запуск кнопкой и автоматический не идут одновременно: общий замок `run.lock`, кнопка ждёт.
- Appinfo (пакеты, варианты запуска, логотип и его позиция) спрашивается у самого Steam консольной командой
  `app_info_print`, ответ читается из `logs/console_log.txt`. Регистр ключей Steam держит небрежно (`BetaKey` и
  `betakey`), поэтому ключи приводятся к строчным. Steam молчит 15 с или ничего не знает об игре — спрашивается
  `api.steamcmd.net`; не ответил и он — простой `logo.png` с CDN (у новых игр его может не быть).
- Установщикам Visual C++ нужен экран, даже в тихом режиме (`/q`): без него они падают с «Failed to create
  window» и висят. У службы экрана нет, поэтому он берётся у процесса Steam (`DISPLAY=:0`).
  Переключение игрового режима и рабочего стола закрывает этот Steam вместе с экраном, и установщик, запущенный
  секундой раньше, виснет. Поэтому программа следит за этим процессом Steam: пропал — установщик снимается,
  программа до минуты ждёт новый Steam и ставит заново на его экран. Нового Steam нет — пакет встанет при следующем
  запуске, неудачной попыткой это не считается. Зависший всё же установщик снимается через 3 минуты (нормальный
  ставится за 3–30 с).
- Свою Visual C++ Wine только изображает: пишет в реестр версию 14.42, а UE5 (Solarpunk) этого мало — его
  загрузчик требует настоящую. После настоящего пакета 14.51 из Steamworks Shared ошибка уходит.
- `ucrtbase.dll` установщик Visual C++ в Proton не заменяет, остаётся вариант Wine — и это хорошо: настоящий
  ucrtbase 14.4x, по отзывам, роняет игры под Proton.
- Проверка «игра запущена» — по процессу Steam `reaper SteamLaunch AppId=<номер ярлыка>`, по процессам с этим
  префиксом и по живому `wineserver` префикса. После установки программа ждёт, пока `wineserver` префикса
  закончит работу, чтобы реестр успел записаться (до минуты, потом `wineserver -k`). Если за это время игру
  запустили, ожидание снимается без `-k`: тот же `wineserver` держит игру.
